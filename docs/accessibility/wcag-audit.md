# WCAG 2.2 AA audit (BIB-53)

Release evidence for NFR-ACCESS-001, NFR-ACCESS-002 and NFR-ACCESS-003 (PRD sections 22, 31 and 32). This file covers the automated checks and the code audit done on 2026-11-15. The manual checks at the end still need a real browser and a screen reader, and their results go in the table there.

## Scope

Core screens: sign-in, Bible reader (with study highlights), study page (desktop regions and the narrow-screen tabs), graph canvas and List View, the Connect dialog, Nodes list and node detail, relationships, conclusions, notes (editor, conflict and read-only), Study Thread, the AI summary, AI suggestions and reasoning path, home, study library, new study, and AI settings.

## Automated evidence

`pnpm --filter @bible-artisan/web test` runs everything below. CI runs it on every PR.

### Contrast

| Pair                                                | Ratio   | Needs |
| --------------------------------------------------- | ------- | ----- |
| ink `#1c1b19` on canvas `#fbfaf7`                   | 16.5:1  | 4.5:1 |
| muted `#5c5a55` on canvas                           | 6.6:1   | 4.5:1 |
| accent `#7a3e12` on canvas (links, outline buttons) | 8.0:1   | 4.5:1 |
| canvas on accent (filled buttons, pressed toolbar)  | 8.0:1   | 4.5:1 |
| white on accent (sign-in buttons)                   | 8.3:1   | 4.5:1 |
| ink on muted/20 (the "AI" badge)                    | 12.3:1  | 4.5:1 |

## Code audit and fixes

| Criterion                    | Finding                                                                                                                                                                                                                                                   | Fix                                                                                                                                                                           |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2.4.7 / 2.4.13 Focus visible | React Flow's stylesheet sets `outline: none` on a focused canvas node (`.react-flow__node.selectable:focus-visible`), which beats the global `:focus-visible` outline. A keyboard user tabbing through the canvas saw no focus until a node was selected. | `globals.css` restores the 2px accent outline with a more specific selector, so it wins whatever order the stylesheets load in.                                               |
| 2.4.7 / 1.4.1 Focus on edges | A focused edge only changed stroke colour, from one grey to another.                                                                                                                                                                                      | A focused or selected edge is drawn 3px wide in accent: a change of width as well as colour.                                                                                  |
| 1.4.11 Non-text contrast     | React Flow draws edges and arrowheads in `#b1b1b7`, about 2:1 on the canvas. Mini map nodes were `#e2e2e2` on white.                                                                                                                                      | Edges, arrowheads and mini map nodes use the muted token (6.6:1), edges 1.5px wide. The connection line uses accent.                                                          |
| 1.4.1 Use of colour          | The graph toolbar's Sources toggle showed its pressed state only by a border colour change (muted to accent).                                                                                                                                             | Pressed toggles also get a 2px border and semibold text. The same applied to the branch Collapse / Show only toggles (they lacked the weight change) and the Nodes list rows. |
| 2.4.1 Bypass blocks          | On the desktop study page every canvas node and edge is a Tab stop, all before the Nodes list.                                                                                                                                                            | A "Skip the canvas" button, shown when focused, sits before the canvas and moves focus to an "End of the canvas" marker after it, which shows while focused.                  |
| 2.4.11 Focus not obscured    | Below 900 px the workspace tab list is `position: sticky; top: 0`. A control focused by Tab could scroll in under it, more so at 200% text when the tabs wrap to several rows.                                                                            | The tab list measures itself into `--workspace-tabs-height`, and the root uses it as `scroll-padding-top`.                                                                    |

Checked and left as they are:

- **Names and roles.** Every rendered screen passes axe's `button-name`, `label`, `link-name`, `aria-*` and list or landmark rules. Each route has its own `<title>` (the study's own title stays out of it for privacy). `<html lang="en">` is set.
- **Focus order.** No positive `tabindex` anywhere. The only `outline-none` elements are `tabIndex={-1}` alert containers that receive programmatic focus after a failed save. They are not controls, and their buttons keep the outline.
- **Colour as the only signal.** Node types, origins, statuses, "Selected", "Duplicate", "Branch root", highlights, the stale summary, "AI suggested" and unsaved tabs are all written in text. The reader marks a referenced verse with a bar and the words "Marked verse". The notes toolbar's pressed buttons change fill from canvas to accent, which is a large lightness change, and `aria-pressed` is set.
- **Accessible authentication (3.3.8).** Email plus a one-time code. The code input has `autocomplete="one-time-code"`, and nothing blocks paste or autofill. Nothing has to be remembered or transcribed except the emailed code, which the criterion allows when paste works.
- **Dragging (2.5.7).** Moving nodes has arrow keys, connecting has the Connect dialog, and everything is also in List View (BIB-28, BIB-29).
- **Target size (2.5.8).** Buttons are at least 28px tall (`text-sm` plus `py-1`). The 12px React Flow connection handles fall under the "equivalent" exception (Connect… does the same thing), and they are not Tab stops.
- **Reflow and 200% text (1.4.4, 1.4.10).** BIB-38 tabs the workspace below 900 px, wraps long words, and makes List View the default graph view on narrow screens. The canvas keeps spatial scrolling, which NFR-ACCESS-003 allows, and List View is its equivalent.
